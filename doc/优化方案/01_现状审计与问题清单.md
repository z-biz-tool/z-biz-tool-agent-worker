## 一、已确认缺陷（源码级证据）

### DEF-01 agent-proxy 零鉴权

- **证据**：`../../agent-proxy/src/server.ts` L28-59 路由无任何 auth 中间件；`../../agent-proxy/src/handlers/common.ts` L34-43 CORS 设为 `Access-Control-Allow-Origin: *`
- **影响**：本机任意进程或恶意网页（通过 DNS rebinding / localhost CORS）可调用 `/v1/chat/completions` 触发 CLI 子进程执行任意 prompt
- **严重度**：P0

### DEF-02 Agent 执行无危险操作拦截

- **证据**：`../../src-tauri/src/commands.rs` L290-292 `assign_task` 直接 `std::thread::spawn` 调用 `run_task_background`，无审批环节；`../../agent-proxy/src/wrappers/claudeCode.ts` L176 `spawn(resolved, args, ...)` 将用户 prompt 原样传入 CLI
- **影响**：Claude Code / Hermes 等 CLI 具备文件系统和 shell 访问能力，任务描述若含破坏性指令将直接执行
- **严重度**：P0

### DEF-03 API Key 明文写入日志

- **证据**：`../../agent-proxy/src/hermesConfig.ts` L49-51 `logger.info('Loaded minimax api_key from hermes config:', key.slice(0, 15) + '...')`；`../../agent-proxy/src/wrappers/claudeCode.ts` L167-168 `logger.info(...ANTHROPIC_API_KEY=${apiKey.slice(0, 15)}...)`
- **影响**：agent-proxy stdout 被 Tauri 管道到 stderr（`../../src-tauri/src/agent_proxy.rs` L81-85），最终进入系统日志或终端输出，key 前 15 字符可辅助暴力破解
- **严重度**：P0

### DEF-04 storage.rs 并发竞态

- **证据**：`../../src-tauri/src/storage.rs` L158-166 `save_task` 执行 `read_tasks()` → 修改 → `write_tasks()`，无文件锁；`../../src-tauri/src/commands.rs` L290 每次 assign_task 都 spawn 新线程，多线程可同时 save_task
- **影响**：两个任务同时完成时，后写者覆盖前写者的全量 JSON，导致数据丢失
- **严重度**：P0

### DEF-05 sidecar 无健康监控与自动重启

- **证据**：`../../src-tauri/src/lib.rs` L51-61 setup 中 spawn 后仅存入 State，无后续监控；`../../src-tauri/src/agent_proxy.rs` L24-69 spawn 函数仅在启动时检测端口，之后不再检查
- **影响**：agent-proxy 进程崩溃（OOM / unhandled exception）后，所有 Agent 操作返回网络错误，用户只看到"执行失败"
- **严重度**：P0

### DEF-06 前端无实时推送，依赖 3s 轮询

- **证据**：`../../src/App.tsx` L57-65 `setInterval(() => store.selectProject(...), 3000)`；`../../src-tauri/src/commands.rs` 全文无 `app.emit` / `tauri::Event` 调用
- **影响**：任务状态变更最多延迟 3s 才可见；无流式输出，用户无法看到 Agent 实时思考过程
- **严重度**：P1

### DEF-07 agent_runner.rs 无重试机制

- **证据**：`../../src-tauri/src/agent_runner.rs` L19-64 `run_agent` 单次 HTTP 调用，失败直接返回 Err
- **影响**：网络瞬断 / CLI 冷启动超时即任务失败，用户需手动点"重试"
- **严重度**：P1

### DEF-08 AppConfig 前后端字段不一致

- **证据**：前端 `../../src/types/index.ts` L73-77 定义 `api_url`；Rust `../../src-tauri/src/models.rs` L96-100 定义 `api_endpoint`
- **影响**：`save_config` / `get_config` 序列化/反序列化字段名不匹配，配置保存后前端读不到正确值
- **严重度**：P1

### DEF-09 src/agent/ 目录为死代码

- **证据**：`../../src/agent/AgentManager.ts` 全文为 SQL Agent 逻辑（query/optimize/analyze/diagnoseError），含 TODO 注释；`../../src/App.tsx` 无任何 import 来自 `./agent`
- **影响**：增加包体积、误导开发者、typecheck 通过但无实际功能
- **严重度**：P2

### DEF-10 CORS 通配符 + 无 Origin 校验

- **证据**：`../../agent-proxy/src/handlers/common.ts` L35 `res.setHeader('Access-Control-Allow-Origin', '*')`
- **影响**：虽然绑定 127.0.0.1，但浏览器中任意页面的 JS 可向 localhost:9099 发请求（simple request 无需 preflight），构成 CSRF 向量
- **严重度**：P1

### DEF-11 prompt 注入到 CLI 参数无转义

- **证据**：`../../agent-proxy/src/wrappers/claudeCode.ts` L184 `cfg.args.map(a => a.replace(/\{prompt\}/g, prompt))`；`../../agent-proxy/src/agentRegistry.ts` L130 hermes 默认 args `['chat', '-q', '{prompt}', '-Q']`
- **影响**：prompt 内容直接替换进 args 数组。虽然 Node.js `spawn` 不经过 shell 解释（无 shell injection），但 CLI 自身可能将特殊字符解释为命令参数
- **严重度**：P2

### DEF-12 session/history 内存无限增长

- **证据**：`../../agent-proxy/src/wrappers/hermes.ts` L30 `const sessionHistories = new Map<string, ChatMessage[]>()`，L288 每次请求 push 到 hist，无 TTL / 大小限制；`../../agent-proxy/src/wrappers/claudeCode.ts` L23 `const activeSessions = new Set<string>()` 只增不减
- **影响**：长时间运行后内存持续增长，最终 OOM
- **严重度**：P1

### DEF-13 Tauri capabilities 配置过于宽松

- **证据**：`../../src-tauri/capabilities/default.json` L7 仅 `"core:default"`，但 `../../src-tauri/Cargo.toml` L19 引入了 `tauri-plugin-shell`
- **影响**：shell 插件已编译进 binary，虽然 capability 未显式授权 shell:execute，但插件存在即扩大攻击面
- **严重度**：P2

### DEF-14 tauri.conf.json CSP 为 null

- **证据**：`../../src-tauri/tauri.conf.json` L23 `"csp": null`
- **影响**：WebView 无内容安全策略，若前端引入外部资源或被 XSS，可执行任意脚本
- **严重度**：P2

## 四、TECH_SPEC 与实现差距

`../../docs/TECH_SPEC.md` 描述的是 **Electron + Express + node-pty** 架构，与实际 **Tauri 2 + Rust + agent-proxy sidecar** 实现严重不符：

| TECH_SPEC 声明 | 实际状态 |
|----------------|----------|
| Electron 桌面壳 | ❌ 实际为 Tauri 2 |
| Express 后端 + REST API | ❌ 实际为 Tauri invoke + agent-proxy HTTP |
| node-pty 伪终端 | ❌ 未使用，直接 spawn 子进程 |
| SSE 推送到前端 | ❌ proxy 侧有 SSE，但 Tauri 后端用 stream:false，前端轮询 |
| 事件引擎 (EventEmitter) | ❌ 未实现，无 TASK_COMPLETED 等事件 |
| context.json 项目上下文 | ❌ 未实现 |
| 父任务自动验收子任务 | ❌ 未实现，仅手动 review |
| Agent 进程池 (Map) | ⚠️ 部分实现：session 映射存在，但非进程池 |
| 任务拆解 Agent | ❌ 未实现 |
| 项目目录隔离 (data/projects/{id}/) | ❌ 实际为全局 JSON 文件 (~/.z-agent-worker/) |

**结论**：TECH_SPEC.md 应标记为"历史设计草稿"，不代表当前实现。后续优化以实际源码为准。
