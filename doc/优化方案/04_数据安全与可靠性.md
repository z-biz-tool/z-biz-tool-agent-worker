## 一、Agent 执行权限边界

### 1.1 核心原则

**Agent 不可自动执行破坏性 shell/文件操作。** 当前 `../../agent-proxy/src/wrappers/claudeCode.ts` L176 `spawn(resolved, args)` 将用户 prompt 原样传入 CLI，CLI 自身具备完整文件系统和 shell 能力（DEF-02）。

### 1.2 权限模型（规划）

| 操作类别 | 风险等级 | 策略 |
|----------|----------|------|
| 读取项目文件 | 低 | 允许，限定 working_dir |
| 写入/创建项目文件 | 中 | 允许，但记录审计日志 |
| 删除文件（rm/unlink） | 高 | 需人工审批 |
| Shell 命令执行 | 高 | 黑名单拦截 + 审批 |
| 网络请求（curl/wget） | 中 | 白名单域名或审批 |
| 系统级操作（sudo/chmod 777） | 极高 | 强制拒绝，不可审批 |

### 1.3 破坏性命令黑名单（初始集）

```
rm -rf / rm -r / rmdir / mkfs / dd / format / del /s
chmod 777 / chown root / sudo *
kill -9 / shutdown / reboot
> /dev/sda / :(){ :|:& };:
git push --force / git reset --hard
DROP TABLE / DROP DATABASE / TRUNCATE
```

### 1.4 实现路径

- **Phase 1**：agent-proxy 在 `executor.ts` 中解析 CLI 输出的 tool_use 事件，匹配黑名单则暂停并发送 `approval_required` SSE 事件
- **Phase 3**：引入平台沙箱（macOS sandbox-exec / Linux bubblewrap），从 OS 层面限制子进程权限
- 文件级改造：`../../agent-proxy/src/executor.ts`（拦截逻辑）、新增 `../../agent-proxy/src/policy.ts`（黑名单+白名单配置）

## 二、危险操作人工审批

### 2.1 审批流设计

```
CLI 输出 tool_use(shell_exec, "rm -rf ./build")
  → agent-proxy 匹配黑名单 → 暂停子进程 stdin（不 kill）
  → SSE event: { type: "approval_required", id, action, detail, risk }
  → Tauri 后端 emit("task-approval-required") → 前端弹窗
  → 用户 Approve → POST /v1/approval/:id {decision:"approve"} → CLI 继续
  → 用户 Reject  → POST /v1/approval/:id {decision:"reject"}  → CLI 终止该操作
  → 超时 60s 无响应 → 自动 Reject
```

### 2.2 审批记录

每次审批决策持久化到 `~/.z-agent-worker/audit_log.json`：
```json
{ "ts": "ISO8601", "task_id": "...", "action": "shell_exec", "detail": "rm -rf ./build", "risk": "high", "decision": "approve", "decided_by": "user" }
```

## 三、密钥与 Token 安全存储

### 3.1 当前问题

| 问题 | 证据 | 影响 |
|------|------|------|
| API Key 写入日志 | `../../agent-proxy/src/hermesConfig.ts` L49-51；`../../agent-proxy/src/wrappers/claudeCode.ts` L167-168 | Key 前 15 字符泄漏到 stdout |
| Key 文件明文存储 | `../../agent-proxy/src/config.ts` L20 `HERMES_API_KEY_FILE = '/tmp/hermes_api_key.txt'` | /tmp 全局可读 |
| 环境变量传递 Key | `claudeCode.ts` L176 spawn env 含 ANTHROPIC_API_KEY | 子进程 /proc/PID/environ 可读（Linux） |

### 3.2 推荐方案

| 层 | 措施 | 优先级 |
|----|------|--------|
| 日志 | 移除所有 `key.slice(0,15)` 输出，替换为 `[REDACTED]` | P0 |
| 存储 | Key 文件权限 0600；长期迁移到 OS keychain（macOS Keychain / Windows Credential Manager） | P0→P1 |
| 传输 | Tauri→proxy 通过 env 传入（进程隔离），不经 HTTP body | P0（已满足） |
| 前端 | API Key 永远不通过 IPC 传到 React 层；设置页仅显示 `sk-***...***` | P1 |
| 轮换 | 支持用户手动更新 Key 后热重载（proxy 无需重启） | P2 |

## 四、代理鉴权与传输加密

### 4.1 本地 Token 鉴权（呼应 [03§2](./03_技术架构与性能优化.md)）

- Tauri spawn proxy 时生成 32-byte 随机 token → env `AGENT_PROXY_TOKEN`
- proxy 校验 `Authorization: Bearer <token>`，`/health` 豁免
- 每次应用启动重新生成，不持久化

### 4.2 传输安全

| 场景 | 当前 | 推荐 |
|------|------|------|
| Tauri ↔ proxy（localhost HTTP） | 明文 | 本地回环可接受；若未来支持远程则必须 TLS |
| proxy ↔ CLI（stdin/stdout） | 进程管道 | 已安全（OS 隔离） |
| proxy ↔ 外部 API（minimaxi.com） | HTTPS | 已满足（`../../agent-proxy/src/hermesConfig.ts` L7 ANTHROPIC_BASE_URL） |
| 前端 ↔ Tauri（IPC） | Tauri 内部通道 | 已安全 |

### 4.3 CORS 收紧

移除 `Access-Control-Allow-Origin: *`（`../../agent-proxy/src/handlers/common.ts` L35），改为仅允许 `tauri://localhost` 或完全移除 CORS（Tauri invoke 不走浏览器 HTTP）。

| 模式 | 替换 | 适用范围 |

## 六、任务隔离

### 6.1 当前隔离级别

| 维度 | 当前状态 | 风险 |
|------|----------|------|
| 进程 | 每任务独立 spawn CLI 子进程 | ✅ 基本隔离 |
| 文件系统 | 所有任务共享同一 working_dir | ❌ 任务 A 可修改任务 B 的文件 |
| 环境变量 | spawn 时继承完整 process.env | ❌ 敏感变量泄漏 |
| Session | hermes 按 sessionId 隔离历史 | ✅ 逻辑隔离 |
| 网络 | 无限制 | ⚠️ CLI 可访问任意外部服务 |

### 6.2 推荐隔离措施

| 措施 | Phase | 说明 |
|------|-------|------|
| 每任务独立 working_dir（`~/.z-agent-worker/workspaces/{task_id}/`） | 1 | 文件级隔离 |
| spawn env 白名单（仅 PATH/HOME/LANG + 必要 API Key） | 1 | 最小权限 |
| 任务完成后清理 workspace（保留产出物到 output） | 2 | 磁盘空间 |
| 平台沙箱 profile（限制文件/网络访问范围） | 3 | OS 级隔离 |
| 资源限制（ulimit / Job Object：max CPU 300s, max RSS 2GB） | 3 | 防 OOM/死循环 |

## 七、供应链安全

| 风险点 | 当前状态 | 建议 |
|--------|----------|------|
| npm 依赖（agent-proxy） | 无 lockfile 审计 | 启用 `npm audit` + CI 集成 |
| Cargo 依赖（src-tauri） | Cargo.lock 存在 | 启用 `cargo audit` |
| CLI 工具来源 | 用户本地安装，proxy 自动发现 | 显示 CLI 路径+版本供用户确认 |
| Tauri sidecar 打包 | `tauri.conf.json` resources 包含 dist/ | 确保 CI 构建产物完整性校验 |
| GitHub Actions | `.github/workflows/build.yml` 使用 actions/checkout@v4 等 | 锁定 commit SHA 而非 tag |

## 八、可靠性保障

| 故障场景 | 当前行为 | 推荐行为 |
|----------|----------|----------|
| proxy 进程崩溃 | 所有操作返回网络错误 | 自动重启（max 3次/5min）+ 前端状态指示 |
| CLI 进程 hang | 等待 10min 超时 | 用户可手动 cancel + 超时后 SIGTERM→SIGKILL |
| tasks.json 写入中断 | 文件损坏 | 原子写入（write .tmp → rename） |
| 磁盘满 | 静默失败 | 启动时检查可用空间 > 100MB，不足则告警 |
| Node.js 未安装 | proxy spawn 失败 | 启动时 resolve_node 检测 + 用户提示安装 |
| 端口 9099 被占用 | 检测并报错（已实现 CAP-11） | 支持自动选择备用端口 |
