## 一、Agent 执行架构与进程/沙箱模型

### 1.1 当前架构

```
Tauri (Rust)
  └─ commands.rs::assign_task
       └─ std::thread::spawn → run_task_background
            └─ agent_runner::run_agent (ureq, blocking, stream:false)
                 └─ HTTP POST 127.0.0.1:9099/v1/chat/completions
                      └─ agent-proxy (Node.js)
                           └─ executor → wrapper.streamChat/syncChat
                                └─ child_process.spawn(claude/hermes/opencode)
```

**问题**：
- 无进程池：每次任务 spawn 新 CLI 进程，冷启动开销大
- 无沙箱：CLI 进程继承完整用户权限（文件系统、网络、shell）
- 无资源限制：CPU/内存/磁盘无 cgroup 或 ulimit 约束
- 线程无管理：`std::thread::spawn` 无 join handle，无法取消

### 1.2 推荐架构

```
Tauri (Rust)
  └─ TaskQueue (tokio, bounded, priority)
       └─ TaskWorker (per-agent semaphore, max_concurrent=N)
            └─ AgentRunner (reqwest, SSE stream, retry+backoff)
                 └─ HTTP → agent-proxy (token auth)
                      └─ SessionRouter → WrapperRegistry
                           └─ Sandbox spawn (working_dir isolated)
                                ├─ 危险操作拦截 → approval_required SSE event
                                └─ 输出流 → Tauri event → 前端
```

**关键设计决策**：

| 决策 | 推荐 | 理由 |
|------|------|------|
| 异步运行时 | tokio（已在 Cargo.toml） | 替代 std::thread，支持取消/超时/并发控制 |
| 任务队列 | bounded mpsc channel + priority heap | 防止无限 spawn，支持优先级调度 |
| 进程隔离 | 每任务独立 working_dir + env 白名单 | 最小权限原则 |
| 沙箱级别 | macOS: sandbox-exec profile; Linux: bubblewrap; Windows: Job Object | 平台原生，无需 Docker |
| 进程取消 | 保存 Child handle → SIGTERM → 5s → SIGKILL | 优雅终止 |

### 1.3 文件级改造点

| 文件 | 改造 |
|------|------|
| `src-tauri/src/commands.rs` | assign_task 改为投递到 TaskQueue，不再直接 spawn thread |
| `src-tauri/src/agent_runner.rs` | 改为 async + SSE 流式消费 + retry |
| 新增 `src-tauri/src/task_queue.rs` | tokio mpsc + Semaphore + priority |
| 新增 `src-tauri/src/sandbox.rs` | 平台沙箱 profile 生成 + spawn wrapper |
| `agent-proxy/src/executor.ts` | 增加 approval 拦截逻辑 |
| `agent-proxy/src/wrappers/*.ts` | spawn 时注入 sandbox 参数 + working_dir |

## 二、agent-proxy 转发与鉴权

### 2.1 当前问题

- 零鉴权（DEF-01）：任何本地进程可调用
- CORS `*`（DEF-10）：浏览器页面可跨域请求
- 无请求频率限制
- 无请求体大小限制（`readBody` 无 max size）

### 2.2 推荐方案：本地 Token 鉴权

```
启动流程：
1. Tauri spawn agent-proxy 时生成随机 token (32 bytes hex)
2. 通过环境变量 AGENT_PROXY_TOKEN 传入子进程
3. agent-proxy 校验每个请求的 Authorization: Bearer <token>
4. /health 端点豁免（用于存活探测）
```

**IPC 契约变更**：

| 端点 | 新增 Header | 说明 |
|------|-------------|------|
| POST /v1/chat/completions | `Authorization: Bearer <token>` | 必须 |
| POST /v1/session/open | `Authorization: Bearer <token>` | 必须 |
| GET /v1/cli-agents | `Authorization: Bearer <token>` | 必须 |
| GET /health | 无 | 豁免 |
| POST /v1/session/:id/cancel | `Authorization: Bearer <token>` | 新增端点 |
| POST /v1/approval/:id | `Authorization: Bearer <token>` | 新增端点 |

**CORS 收紧**：
- 移除 `Access-Control-Allow-Origin: *`
- 仅允许 `tauri://localhost` 和 `http://localhost:5173`（dev）
- 或直接移除 CORS（Tauri invoke 走 IPC 不走 HTTP）

### 2.3 文件级改造点

| 文件 | 改造 |
|------|------|
| `src-tauri/src/agent_proxy.rs` | spawn 时生成 token，通过 env 传入 |

## 三、流式输出贯通

### 3.1 当前断点

```
CLI stdout → agent-proxy (SSE 已实现) → ❌ Tauri 后端 (stream:false) → ❌ 前端 (轮询)
```

proxy 侧 SSE 能力完整（`handlers/chat.ts` L64-80），但 Tauri 后端 `agent_runner.rs` L49 和 `agent_session.rs` L111 均使用 `"stream": false`。

### 3.2 推荐方案

```
CLI stdout → agent-proxy SSE → Tauri reqwest stream → app.emit("task-output") → 前端 listen
```

**Tauri 后端改造**（`agent_runner.rs`）：
```rust
// 伪代码
pub async fn run_agent_stream(
    app: &AppHandle,
    task_id: &str,
    cli_type: &str,
    prompt: &str,
    cancel: CancellationToken,
) -> Result<String, String> {
    let resp = client.post(url).json(&body).send().await?;
    let mut stream = resp.bytes_stream();
    let mut full = String::new();
    while let Some(chunk) = stream.next().await {
        if cancel.is_cancelled() { break; }
        let delta = parse_sse_delta(&chunk)?;
        full.push_str(&delta);
        app.emit("task-output", TaskOutputPayload { task_id, delta, full_len: full.len() })?;
    }
    app.emit("task-done", TaskDonePayload { task_id, output: full })?;
    Ok(full)
}
```

**前端改造**（`workerStore.ts`）：
```typescript
// 伪代码
listen<TaskOutputPayload>("task-output", (event) => {
  set(state => ({
    streamingOutputs: { ...state.streamingOutputs, [event.payload.task_id]: event.payload.full }
  }));
});
```

### 3.3 SSE 事件类型契约

| 事件名 | Payload | 触发时机 |
|--------|---------|----------|
| `task-output` | `{ task_id, delta, full_len }` | 每个 token/chunk |
| `task-tool-use` | `{ task_id, tool, input, risk_level }` | CLI 报告工具调用 |
| `task-approval-required` | `{ task_id, approval_id, action, detail }` | 危险操作待审批 |
| `task-done` | `{ task_id, output, duration_ms, token_count? }` | 执行完成 |
| `task-error` | `{ task_id, error, retryable }` | 执行失败 |
| `task-status` | `{ task_id, old_status, new_status }` | 状态变更 |

## 四、任务队列与并发控制

### 4.1 当前问题

- `commands.rs` L290：每次 assign_task 无条件 `std::thread::spawn`
- 无并发上限：100 个任务同时分配 = 100 个线程 + 100 个 CLI 进程
- 无优先级：FIFO 都不保证（线程调度随机）
- 无取消：线程 spawn 后无法中断

### 4.2 推荐方案

```rust
// task_queue.rs 核心结构
pub struct TaskQueue {
    tx: mpsc::Sender<TaskEnvelope>,
    handles: DashMap<String, CancellationToken>,  // task_id → cancel token
}

pub struct TaskEnvelope {
    pub task_id: String,
    pub agent_id: String,
    pub cli_type: String,
    pub prompt: String,
    pub priority: u8,       // 0=最高
    pub cancel: CancellationToken,
}

// Worker pool: per-agent semaphore
// 全局并发上限: Semaphore::new(MAX_CONCURRENT)  // 默认 4
// 单 Agent 并发: Semaphore::new(MAX_PER_AGENT)   // 默认 1
```

**调度策略**：
- 全局最大并发 4（可配置）
- 单 Agent 最大并发 1（串行，保证 session 上下文连贯）
- 优先级队列：priority 小的先执行
- 超时：单任务最大 10min（与 proxy processTimeoutMs 对齐）
- 取消：CancellationToken → drop reqwest stream → proxy kill 子进程

### 4.3 文件级改造点

| 文件 | 改造 |
|------|------|
| 新增 `src-tauri/src/task_queue.rs` | 队列 + worker pool + semaphore |
| `src-tauri/src/commands.rs` | assign_task/retry_task 改为 queue.submit() |
| `src-tauri/src/lib.rs` | manage(TaskQueue) + setup 中启动 worker |
| 新增 `src-tauri/src/cancel.rs` | cancel_task command |

## 五、状态管理与存储优化

### 5.1 当前问题

- JSON 全量读改写（`storage.rs`）：每次 save_task 读取整个 tasks.json → 修改 → 写回
- 无文件锁：并发线程竞态（DEF-04）
- 无原子写入：写到一半崩溃 = 文件损坏
- 数据量增长后性能线性退化

### 5.2 短期方案（Phase 1）：文件锁 + 原子写入

```rust
// storage.rs 改造
use fs2::FileExt;  // 或 fd-lock crate

pub fn save_task(task: &Task) {
    let file = tasks_file();
    let lock_path = file.with_extension("lock");
    let lock_file = File::create(&lock_path).unwrap();
    lock_file.lock_exclusive().unwrap();  // 阻塞锁
    
    let mut tasks = read_tasks();
    if let Some(idx) = tasks.iter().position(|t| t.id == task.id) {
        tasks[idx] = task.clone();
    } else {
        tasks.push(task.clone());
    }
    
    // 原子写入：先写 .tmp 再 rename
    let tmp = file.with_extension("tmp");
    fs::write(&tmp, serde_json::to_string_pretty(&tasks).unwrap()).unwrap();
    fs::rename(&tmp, &file).unwrap();  // POSIX 原子操作
    
    lock_file.unlock().unwrap();
}
```

### 5.3 长期方案（Phase 5）：SQLite

- 使用 `rusqlite` 或 `sqlx` + SQLite
- 表：projects / agents / tasks / task_messages / audit_log
- 优势：事务、并发安全、索引查询、增量更新
- 迁移：提供 JSON → SQLite 一次性迁移脚本

### 5.4 前端状态管理

当前 `workerStore.ts` 每次操作后调用 `selectProject` 全量刷新（L71, L77, L82...）。

**优化**：
- 引入 Tauri event 监听，增量更新 store
- `task-status` 事件 → 仅更新对应 task 的 status 字段
- `task-output` 事件 → 追加到 streamingOutputs map
- 减少 invoke 调用频率，降低 IPC 开销

| `agent_runner.rs` L15 | 180s read timeout | 无 |

| agent-proxy `config.ts` L35 | 10min processTimeoutMs | 无 |

### 6.2 推荐重试策略

```rust
// agent_runner.rs 改造
const MAX_RETRIES: u32 = 3;
const BASE_DELAY: Duration = Duration::from_secs(2);

pub async fn run_agent_with_retry(cli_type: &str, prompt: &str) -> Result<String, String> {
    let mut last_err = String::new();
    for attempt in 0..MAX_RETRIES {
        match run_agent_once(cli_type, prompt).await {
            Ok(output) => return Ok(output),
            Err(e) => {
                last_err = e;
                if !is_retryable(&last_err) { break; }
                let delay = BASE_DELAY * 2u32.pow(attempt);  // 2s, 4s, 8s
                tokio::time::sleep(delay).await;
            }
        }
    }
    Err(last_err)
}

fn is_retryable(err: &str) -> bool {
    err.contains("timeout") || err.contains("connection refused") 
    || err.contains("502") || err.contains("503")
}
```

### 6.3 超时分层

| 层 | 超时 | 说明 |
|----|------|------|
| Tauri → proxy connect | 2s | proxy 未启动时快速失败 |
| Tauri → proxy read (SSE) | 无硬超时，靠 CancellationToken | 流式不能设 read timeout |
| proxy → CLI process | 10min（现有） | 保留 |
| 单任务总超时 | 15min | 超时后 cancel + 标记 waiting |
