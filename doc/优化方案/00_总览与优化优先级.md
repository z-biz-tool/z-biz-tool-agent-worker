## 一、项目定位与独特价值

**z-biz-tool-worker** 是一个 Tauri 2 桌面应用，定位为 **AI Agent 任务看板**：用户创建项目、挂载本地 CLI Agent（Claude Code / Hermes / OpenCode）、下发任务、Agent 自动执行、用户验收结果。

### 独特价值（区别于通用 Chat UI）

| 维度 | 价值 |
|------|------|
| 任务生命周期管理 | todo → doing → waiting → review → done 五态流转，含父子任务拆解 |
| 多 Agent 并行 | 同一项目可挂载多个 CLI Agent，各自独立 session，任务可分配给不同 Agent |
| 本地 CLI 桥接 | agent-proxy 将 OpenAI 兼容 API 翻译为本地 CLI 子进程调用，无需云端部署 |
| 验收闭环 | Agent 产出进入 review 态，用户人工通过/驳回，驳回后重新执行 |
| 桌面原生体验 | Tauri 2 打包为 .app/.exe/.deb，sidecar 进程随应用启停 |

### 主应用与 agent-proxy 的关系

```
┌─────────────────────────────────────────────────────┐
│  Tauri 主应用 (Rust + React)                        │
│  ┌───────────┐    invoke     ┌──────────────────┐   │
│  │ React UI  │◄────────────►│ Rust commands.rs │   │
│  │ (轮询3s)  │              │ agent_runner.rs  │   │
│  └───────────┘              │ agent_session.rs │   │
│                              └────────┬─────────┘   │
│                                       │ HTTP        │
│                                       ▼             │
│  ┌─────────────────────────────────────────────┐    │
│  │ agent-proxy (Node.js sidecar, :9099)        │    │
│  │  /v1/session/open  /v1/chat/completions     │    │
│  │  Wrappers: ClaudeCode | Hermes | OpenCode   │    │
│  └────────────────────┬────────────────────────┘    │
│                       │ spawn subprocess            │
│                       ▼                             │
│            claude / hermes / opencode CLI           │
└─────────────────────────────────────────────────────┘
```

- **主应用**：项目管理、Agent 注册、任务 CRUD、状态流转、UI 展示
- **agent-proxy**：CLI 发现、session 路由、子进程 spawn、SSE/JSON 输出解析
- **通信**：主应用通过 `ureq`/`reqwest` 调用 agent-proxy 的 HTTP API；agent-proxy 由 Tauri setup 阶段 spawn，Exit 时 kill

## 四、分阶段能力演进

### Phase 1：安全基线 + 可靠性（2 周）
- agent-proxy 本地 token 鉴权
- 危险操作拦截 + 人工审批流
- API Key 脱敏
- storage 文件锁 / 原子写入
- sidecar 健康检查 + 自动重启

### Phase 2：实时可观测（2 周）
- SSE 流式输出贯通到前端（替换 3s 轮询）
- Tauri event 推送任务状态变更
- 执行日志面板（工具调用、token 消耗）
- 任务超时告警

### Phase 3：任务编排增强（3 周）
- 父子任务自动验收 + 事件驱动
- 任务队列 + 并发限制 + 优先级
- Agent 能力声明（tools / 可访问目录）
- 任务上下文快照 + 回放

### Phase 4：多 Agent 协作（3 周）
- Agent 间消息传递（通过 context.json）
- 任务拆解 Agent 自动生成子任务
- 多 Agent 竞争领取 / 负载均衡
- 执行成本统计（token / 时间）

### Phase 5：生产化（2 周）
- SQLite 替换 JSON 文件存储
- 数据导出/导入
- 自动更新（Tauri updater）
- CI 集成测试 + 故障注入

## 五、核心原则（贯穿全部文档）

1. **Agent 不自动执行破坏性操作** — 任何 shell 命令、文件删除、网络请求必须经过审批或白名单
2. **危险操作需人工审批** — review 态不仅是结果验收，执行前的危险动作也需确认
3. **密钥不泄漏** — API Key 不写日志、不存明文 JSON、不通过 IPC 传输到前端
4. **任务隔离** — 不同任务的工作目录、环境变量、session 互不干扰

## 七、对标理念参考

| 产品 | 借鉴点 | 不复制 |
|------|--------|--------|
| Devin | 任务级 Agent 自治 + 人工 checkpoint | 云端沙箱架构 |
| Cursor Agent | 工具调用审批流（Apply/Reject） | IDE 集成方式 |
| OpenHands | 事件流架构 + 沙箱隔离 | Docker 容器方案 |

本项目取"任务看板 + 本地 CLI 桥接"的独特定位，不追求云端沙箱或 IDE 内嵌，而是在桌面端实现安全可控的多 Agent 任务编排。
